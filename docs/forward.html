Chapter 05

The forward pass

Sixty-four neurons at once is a matrix multiply. The whole network is three lines of NumPy, and the shapes tell you almost everything.

Entry 05 · snake_ai/network.py: QNetwork.forward, __init__

From one neuron to a layer

A layer is many neurons reading the same inputs. Neuron j has its own weights, one per input. Stack those weight columns side by side and you get a matrix W1 of shape 11 × 64: row i is input i, column j is neuron j. Then all 64 weighted sums at once are one matrix product:

snake_ai/network.pyforward
z1 = x @ self.W1 + self.b1      # (n, 11) @ (11, 64) + (64,) -> (n, 64)
h = np.maximum(0.0, z1)         # ReLU, same shape
q = h @ self.W2 + self.b2       # (n, 64) @ (64, 3) + (3,)  -> (n, 3)
return q, (x, h)

That is the whole network. @ is matrix multiplication. The bias b1 has shape (64,), and NumPy broadcasts it: adds it to every row. The output layer has no activation, because a Q-value is a guess of future reward, which can be any number, positive or negative.

Batches for free

The first dimension, n, is the batch. Nothing in those three lines cares whether n is 1 or 64. When the agent plays, it passes one state and gets three numbers. When it learns, it passes 64 remembered states and gets a 64 × 3 block of Q-values, in one call. Doing 64 at once is much faster than a Python loop, because the loop runs inside NumPy's compiled code.

The function also returns a cache: the input x and the hidden activations h. Backpropagation needs both (chapter 6), and keeping them saves recomputing the forward pass.

Counting parameters

W1 has 11 × 64 = 704 numbers, b1 64, W2 64 × 3 = 192, b2 3. Total 963. A test checks this exact number. That is tiny: the PNG of the training curve is 70 KB, the trained model file 10 KB.

Starting weights

Weights cannot all start at zero. Every hidden neuron would compute the same thing and get the same gradient, and they would stay identical forever. Random starting values break that symmetry. But the size of those values matters.

If the weights are too large, values grow layer by layer and the first Q-values are huge, so the first errors and updates are huge. If they are too small, the signal fades. He initialisation picks the spread so the signal keeps about the same size through a ReLU layer: a normal distribution with variance 2 / fan_in, where fan_in is the number of inputs to the layer. The 2 is there because ReLU zeroes about half its inputs, which halves the variance; the 2 puts it back. For the linear output layer I use variance 1 / fan_in, since there is no ReLU after it.

self.W1 = rng.normal(0.0, np.sqrt(2.0 / n_inputs), size=(n_inputs, n_hidden))
self.b1 = np.zeros(n_hidden)
self.W2 = rng.normal(0.0, np.sqrt(1.0 / n_hidden), size=(n_hidden, n_outputs))
self.b2 = np.zeros(n_outputs)

Biases can start at zero: the random weights already make the neurons different.

Saving and loading

save() writes the four arrays to a .npz file (NumPy's zip of arrays) with the training config as JSON next to them, and load() reads the shapes back from the arrays, so a model with 16 hidden units loads without being told. The guide uses the same file: tools/guide/export_data.py copies the weights into the page, and the page runs this exact forward pass in JavaScript. A self-test checks that the browser and Python give identical Q-values on 60 positions and play the same 259-step game move for move.

IN:How did you initialise the weights, and why does it matter?
OUT:

Random normal with He scaling, standard deviation sqrt(2 / fan_in) for the ReLU layer and sqrt(1 / fan_in) for the linear output, biases at zero. Random breaks the symmetry; if all weights were equal, all hidden units would learn the same thing. The scale keeps activations about the same size from layer to layer, so the first Q-values and gradients are reasonable instead of exploding or vanishing. The factor 2 compensates for ReLU zeroing about half its inputs.
