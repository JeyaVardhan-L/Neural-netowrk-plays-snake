The dilemma

At the start, the network's Q-values are random. If the agent always picks the highest one, it plays the same arbitrary moves every time, and it only ever learns about those moves. This is the exploration–exploitation trade-off: exploit what you know to score now, or explore something else to find out whether it is better.

Epsilon-greedy handles it with one number. With probability ε, pick a random move. Otherwise pick the move with the highest Q-value.

snake_ai/agent.pyAgent.act
def act(self, state, epsilon=0.0):
    if self.rng.random() < epsilon:
        return int(self.rng.integers(N_ACTIONS))
    return int(np.argmax(self.net.predict(state)))

A test checks both halves: with ε = 1, 3,000 moves come out within 4 percentage points of a third each; with ε = 0, the move is always the argmax.

A schedule

Early on there is nothing worth exploiting, so ε should be high. Later the agent knows a lot, and random moves mostly just kill it. So ε decays: it starts at 1.0 (all random), falls in a straight line to 0.01 over the first 150 games, then stays there. I decay per game rather than per step, so that a long game late in training does not burn through the schedule faster than a short one early on.

Evaluation uses ε = 0

When measuring the agent, I turn exploration off. The 0.01 floor during training costs a little: on a game of 400 steps, about 4 moves are random, and one bad random move next to the body is enough to end a game. That is part of why the greedy evaluation (26.4) scores higher than the last 100 training games (23.5).

What the experiment showed

I trained four schedules, 5 seeds each. Here are the learning curves.

Two things stand out. First, each curve takes off roughly when its ε gets small, because a mostly-random snake cannot eat many apples even if it has learned something. Second, and I did not expect this, even no decay at all (ε = 0.01 from the first game) learned fine, scoring 26.6.

My explanation is that the problem is small and death is cheap. There are only 256 possible inputs, and every crash quickly sends the agent back to the start with its Q-values changed by a −10 target. The changing values alone push a greedy agent into new situations. In a big state space with rare rewards, this would not be true: there, exploration is the whole problem. I would not drop it on a harder game, but I would also not claim it is what made this one work.

OUT:

Exploiting means taking the action you currently believe is best; exploring means trying others to learn whether they are better. If you only exploit, you never correct wrong early estimates. I used epsilon-greedy: a random move with probability epsilon, decayed linearly from 1 to 0.01 over the first 150 games, and zero during evaluation.

In my ablation, the schedule changed the final score by only a few points, and even a constant 0.01 worked, because the state space has only 256 inputs and crashes reset the agent quickly. On a harder problem I would expect exploration to matter much more.
