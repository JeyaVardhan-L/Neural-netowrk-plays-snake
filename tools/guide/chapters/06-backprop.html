The error we train on

Suppose that, for some remembered state s, we know the number the network should have output for the move a that was played. Call it the target y. (Where y comes from is chapter 8.) The error is the squared difference, averaged over the batch:

L = mean( (Q(s, a) − y)2 )      ∂L / ∂Q(s, a) = 2 (Q(s, a) − y) / n

This is the mean squared error. Squaring makes every error positive and punishes big misses more than small ones. Note what is not in it: the two moves that were not played. We have no evidence about them from this step, so their outputs get a gradient of exactly zero.

snake_ai/network.pyq_loss
rows = np.arange(n)
error = q[rows, actions] - targets          # one number per sample
loss = float(np.mean(error ** 2))
dq = np.zeros_like(q)
dq[rows, actions] = 2.0 * error / n         # only the move that was played

The chain rule, one line at a time

We want ∂L/∂W for every weight: how much the loss changes if that weight changes a little. The chain rule says that if L depends on q, and q depends on W2, then ∂L/∂W2 = ∂L/∂q · ∂q/∂W2. Backprop applies this to each line of forward, starting from the last.

Line 3, q = h @ W2 + b2. Output k is Σj hj W2jk + b2k. Change W2jk a little and qk changes by hj times that. So ∂L/∂W2jk = hj · dqk, summed over the batch. As matrices, that is h.T @ dq, shape (64, n) @ (n, 3) = (64, 3), the same shape as W2, as every gradient must be. The bias adds directly, so its gradient is dq summed over the batch.

To keep going we also need the gradient for h. Hidden unit j feeds all three outputs, so its gradient collects from all three: dhj = Σk dqk W2jk, which is dq @ W2.T. The error flows back through the same weights it came forward through, transposed.

Line 2, h = max(0, z1). Where the unit was on, ReLU's slope is 1 and the gradient passes unchanged. Where it was off, the slope is 0 and the gradient stops. So dz1 = dh * (h > 0).

Line 1, z1 = x @ W1 + b1. Exactly the same pattern as line 3: dW1 = x.T @ dz1 and db1 = dz1.sum(axis=0). We do not need the gradient for x; inputs are not learned.

snake_ai/network.pybackward
dW2 = h.T @ dq                  # q = h @ W2 + b2
db2 = dq.sum(axis=0)
dh = dq @ self.W2.T
dz1 = dh * (h > 0)              # h = max(0, z1)
dW1 = x.T @ dz1                 # z1 = x @ W1 + b1
db1 = dz1.sum(axis=0)

Proving it: the gradient check

Hand-written gradients are easy to get wrong in ways that still train, just badly. The classic referee is the numerical gradient. Nudge one weight up by a tiny h, measure the loss, nudge it down, measure again:

∂L/∂w ≈ ( L(w + h) − L(w − h) ) / 2h

This needs two forward passes per weight, far too slow for training, but it uses nothing except the forward pass, so it is very hard to get wrong. test_gradient_check does it for every one of the weights of an 11 → 16 → 3 network on a random batch of 8, with h = 10−6, and compares with backward() using the relative error |a − b| / (|a| + |b|). It must be below 10−6; in practice it is around 10−9.

The "forget the 2" bug is the instructive one. Every gradient is exactly half of the truth, so training still works, just as if the learning rate were halved. Nothing crashes, the curves look plausible, and without a gradient check you could carry that bug for months.
