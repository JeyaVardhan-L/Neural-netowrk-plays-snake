The board is just coordinates

An agent does not need pixels. The game lives in SnakeGame, a class with no graphics at all. The board is 20 × 20 cells, and a cell is a pair (x, y). Like rows on a screen, y grows downwards, so "up" is (0, −1). Getting this wrong once flips every "food up" input, and the network learns nonsense without any error message.

The snake is a deque of cells, head first. A deque (double-ended queue) can add at the front and remove at the back in constant time, which is exactly what moving a snake is: a new head appears at the front, the tail disappears at the back. Next to it I keep a set of the same cells, because "is this cell part of the body?" gets asked several times per step and a set answers in constant time.

A new game puts a snake of length 3 in the middle, heading right, and drops the food on a random free cell. The random generator is NumPy's default_rng(seed), owned by the game, so a seed reproduces every food position.

One step, in order

step(action) is the whole game. It follows the shape every reinforcement-learning environment uses: action in, (state, reward, done, info) out.

  1. Turn: work out the new heading from the relative action (chapter 3).
  2. Compute the new head: old head plus the heading.
  3. If the new head is not the food, pop the tail first.
  4. If the new head is off the board or in the body: crash, reward −10, game over.
  5. Otherwise push the new head. If it was the food: score +1, reward +10, new food. The tail was never popped, so the snake is one cell longer.
  6. If the snake has gone 100 × length steps without eating, stop the game (a time-out).

The tail rule

Step 3 is the subtle one. Picture a snake curled in a tight square, its head right next to its own tail. It moves into the tail's cell. Is that a crash? In real Snake, no: on the same tick the tail moves out of the way. If you check for a collision before removing the tail, the snake dies there, and the agent learns that chasing its own tail is deadly when it is actually one of the safest things a long snake can do.

Two kinds of "game over"

A crash and a time-out both end the game, but they mean different things, and info["terminal"] keeps them apart.

A crash is a terminal state: the game really is over and nothing good can follow. A time-out is a truncation: I stopped a snake that was circling forever, but the game itself could have continued. When we get to Q-learning, a terminal step means "the future is worth exactly 0", while a truncated step still has a future. Treating a time-out as a crash would teach the agent that some ordinary positions are fatal, for reasons it cannot see. So a time-out gets reward 0 and terminal = False.

In practice the trained snake never times out: all 100 evaluation games end in a body crash. The limit matters early, when a random snake can wander for hundreds of steps.

Rewards

The whole learning signal is three constants at the top of the file: REWARD_FOOD = 10, REWARD_CRASH = −10, REWARD_STEP = 0. There is no reward for moving towards the food. I left that out on purpose: shaping rewards by hand is a way of telling the agent the answer, and I wanted to see whether it could find "go towards the food" from +10 alone. It can (chapter 13).

Testing a game

Games are easy to get subtly wrong, so tests/test_game.py places snakes by hand and checks the result: moving forward keeps the length, eating grows it, the wall and body crash, the tail cell is legal, a time-out is not terminal, food never lands on the snake, and the same seed plays the same game. Fifteen tests, and they run in a fraction of a second.

IN:Why do you remove the tail before checking for a collision?
OUT:

Because the tail moves on the same tick as the head. If the head steps into the cell the tail is leaving, that is a legal move in Snake. Checking first would count it as a crash, so the agent would get −10 for a safe move and learn to fear following its own tail. When the snake eats, the tail stays, but the food can never be on the tail, so there is no conflict. I have a test that puts the snake in a 2 by 2 loop and checks that this move survives.
