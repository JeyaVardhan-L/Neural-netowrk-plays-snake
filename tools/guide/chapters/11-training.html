The loop

All the pieces from the last nine chapters fit into a dozen lines. For each game: pick ε for this game, reset the board, and until the game ends: act, step, remember, learn.

snake_ai/training.pytrain
for g in range(games):
    eps = epsilon_for_game(g, cfg)
    state = game.reset()
    done = False
    while not done:
        action = agent.act(state, eps)
        next_state, reward, done, info = game.step(action)
        agent.remember(state, action, reward, next_state, info["terminal"])
        loss = agent.learn()
        state = next_state

One gradient step per game step, on a batch of 64. Each game writes one row to log.csv: game number, score, steps, epsilon, mean loss, how it ended, the record so far and the elapsed time. At the end the weights go to model.npz and a 100-game evaluation to summary.json.

Reading the curve

The first 100 games are almost all random moves, and the scores show it: 74 apples in 100 games, the first one in game 22. Learning is happening (the memory fills, the network starts to tell crashes apart from safe moves), but with ε above 0.35 the snake cannot act on it.

Then it takes off. The 20-game average passes 10 apples at game 148 and 20 at game 159. Within about 15 games the agent goes from barely competent to its final level. After that the average sits around 24 for the rest of the run, with single games anywhere from 2 to 47. That noise is real, not a training problem: one game's score depends heavily on where the food happens to land relative to the body.

The loss went up

In supervised learning, a rising loss means something is broken. Here the mean loss per game went from 0.46 in the first 50 games to 3.29 in the last 100, while the score went from almost 0 to 24. Both are correct.

The targets are not fixed labels; they are built from the agent's own play. A random snake mostly sees zeros and the odd −10, which are easy to predict. A good snake eats every 15 steps or so, so its Q-values are large, and the target for every move includes a bootstrapped guess about apples several steps away. Bigger, noisier targets mean bigger squared errors. In reinforcement learning, watch the reward, not the loss.

Why so fast

The whole run is 99,213 game steps and about 98,000 gradient steps on batches of 64, with a network of 963 parameters. Each update is a few tiny matrix products. Training spends most of its time in Python overhead, not arithmetic, which is also why using more BLAS threads made no difference (12.2 s with one thread, 12.3 s with the default). The late games dominate the time because they are long: the first 150 games took 1.4 s, the last 250 took 10.5 s.

Measuring it properly

A training score is a poor measure: it includes random moves, and the network changes during each game. So evaluate() plays 100 fresh games with ε = 0 and frozen weights, on boards from a fixed seed:

Every game ends with the snake running into itself. None hit a wall, none timed out. Chapter 14 looks at how.

One caution I learned here: evaluation numbers depend on the boards. The same seed-0 model scored 28.46 in the ablation study, where evaluation used a different board seed. Both are honest; they just differ by the luck of the food. That is why chapter 12 compares averages over 5 training seeds, never single runs.

Reproducible to the digit

Every source of randomness takes a seed: the game's food, the network's initial weights, epsilon's coin flips and the memory's sampling. Running python train.py twice gave 26.43 both times. On another machine, small floating-point differences in NumPy's maths libraries can change a move somewhere and the numbers will drift slightly, but they should land in the same range.

I evaluate separately: 100 new games with epsilon zero and frozen weights, on boards from a fixed seed, and report mean, median, spread and how games ended.
