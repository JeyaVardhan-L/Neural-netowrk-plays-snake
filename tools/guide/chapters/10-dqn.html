The problem with learning as you go

The simplest way to train is to update the network on each step as it happens. Two things go wrong when the Q-function is a neural network:

  • Correlated data. Consecutive steps are nearly the same: the snake moving along a wall produces dozens of almost identical states in a row. Gradient descent assumes samples are roughly independent. Feed it a long run of similar ones and it overfits to whatever it saw last, forgetting the rest.
  • A moving target. The target y = r + γ max Q(s′, a′) uses the same network we are updating. Every step changes the network, which changes the target, which we then chase. It can feed back on itself and oscillate or diverge.

The 2015 DQN paper from DeepMind, which learned Atari games from pixels, added one fix for each.

Replay memory

Store every transition (s, a, r, s′, terminal) in a big buffer, and train on random batches from it. A random batch mixes steps from many moments and many games, which breaks the correlation. It also reuses each transition many times instead of once, which makes learning more sample efficient.

My buffer is a ring buffer: five NumPy arrays allocated once at full size (100,000 rows), a write position pos and a count size. Each push writes at pos and advances it with (pos + 1) % capacity, so once full, the oldest transition is overwritten. Nothing is ever appended or shifted, and sampling is one fancy-indexing call per array. Learning waits until 1,000 transitions are stored, so the first batches are not 64 copies of the first few steps.

Target network

Keep a second copy of the network, the target network, and use it only to compute max Q(s′, a′) in the targets. Do not train it. Every 500 updates, copy the online network's weights into it. Between copies, the targets stay still, so each stretch of training is an ordinary regression problem with fixed labels.

if cfg.target_sync > 0 and self.updates % cfg.target_sync == 0:
    self.target.load_state(self.net.params)

load_state copies values into the target's existing arrays. It must be a copy: if the target simply pointed at the online network's arrays, it would change with every update and the whole idea would silently disappear. test_target_network_syncs checks that the two differ after 4 updates and are equal after the 5th, with target_sync=5. The main run made about 98,000 updates, so the target was refreshed about 196 times.

Were they worth it?

I trained four versions for 400 games, 5 seeds each: both tricks, no target network (target_sync=0, the target is the online network), no replay (a memory of 1 and a batch of 1, so each step is used once, immediately), and neither.

The honest result: on this problem, neither trick changes the final score. All four versions finish between 25 and 28.5 in evaluation, and the differences are smaller than the spread between seeds. What replay does change is speed: without it, the curve rises about 40 games later, because each transition is used once and then discarded, instead of about 64 times on average (98,000 updates instead of roughly 64 times.times; 64 samples, spread over 99,000 stored transitions).

I think the reason is, again, the 256 inputs. The instabilities that replay and target networks fix come from many similar-looking states sharing weights, so that an update for one state drags the values of others around. With 256 distinct, discrete inputs and a network that can easily represent all of them, there is little interference to fight. On pixels, where neighbouring states really are almost identical, the original paper found both tricks essential. I kept both in the default: they cost almost nothing, and it is the standard DQN design.

IN:Why does DQN use experience replay and a target network?
OUT:

Replay stores transitions and trains on random batches, which breaks the strong correlation between consecutive steps and reuses each experience many times. The target network is a periodically copied, frozen version of the Q-network used to compute the bootstrap targets, so the target does not shift with every gradient step, which reduces oscillation and divergence.

In my snake, I measured both. Neither changed the final score beyond seed noise, because the state space is tiny, but without replay learning took about 40 more games. I would expect both to matter much more with high-dimensional inputs like pixels.
